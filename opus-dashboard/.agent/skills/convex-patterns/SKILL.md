# Convex Patterns

> **Note:** Low-level Convex syntax rules (validators, function registration, cron syntax, pagination, etc.) are covered separately in the project's Cursor rules file. This skill covers *project-specific* conventions layered on top of those.

This project uses Convex as its backend and database. Every piece of backend code must follow these rules without exception.

## Rule 1 — Always filter by `orgId`

Every table has an `orgId` field. Every query and mutation must scope to the current org. Multi-tenancy is enforced at the query level — never rely on UI or middleware alone.

```typescript
// ✅ Correct
const bookings = await ctx.db
  .query("bookings")
  .withIndex("by_org", (q) => q.eq("orgId", orgId))
  .filter((q) => q.eq(q.field("isDeleted"), false))
  .collect();

// ❌ Wrong — missing orgId scope
const bookings = await ctx.db.query("bookings").collect();
```

## Rule 2 — Soft deletes only

Never call `ctx.db.delete()`. Set `isDeleted: true` and `deletedAt: Date.now()`. Always filter out soft-deleted records unless building an admin/audit view.

```typescript
// ✅ Correct
await ctx.db.patch(id, { isDeleted: true, deletedAt: Date.now() });

// ❌ Wrong
await ctx.db.delete(id);
```

## Rule 3 — Money is always integers in minor units

Store all monetary values as integers (pence, cents). `2500` = £25.00. Never use floats or formatted strings.

```typescript
// ✅ Correct
priceMinorUnits: 2500

// ❌ Wrong
price: 25.00
price: "£25.00"
```

## Rule 4 — Timestamps are Unix milliseconds

Use `Date.now()` everywhere. Never store ISO strings or Date objects.

```typescript
// ✅ Correct
createdAt: Date.now()

// ❌ Wrong
createdAt: new Date().toISOString()
```

## Rule 5 — Always use named indexes

Never use `.filter()` as the primary data access path — it is a full table scan. Always query via a named `.withIndex()`. Use `.filter()` only for secondary filtering after an index narrows the result set.

```typescript
// ✅ Correct
await ctx.db
  .query("services")
  .withIndex("by_org_active", (q) =>
    q.eq("orgId", orgId).eq("isActive", true)
  )
  .collect();

// ❌ Wrong — full table scan
await ctx.db
  .query("services")
  .filter((q) => q.eq(q.field("orgId"), orgId))
  .collect();
```

## Rule 6 — Write to `audit_log` on every significant mutation

Bookings, cancellations, and AI-triggered actions must produce an `audit_log` entry. The log is append-only: never update or delete audit rows. Always include `before`/`after` snapshots.

```typescript
await ctx.db.insert("audit_log", {
  orgId,
  actorType: "staff",        // "user" | "staff" | "ai" | "system" | "webhook"
  actorId: staffMemberId,
  action: "booking.cancelled",
  resourceType: "bookings",
  resourceId: bookingId,
  before: existingBooking,
  after: { ...existingBooking, status: "cancelled", cancelledAt: Date.now() },
  createdAt: Date.now(),
});
```

## Rule 7 — External API calls go in Actions, not Mutations

Mutations are for database writes only. Never call Twilio, Resend, Anthropic, or any external service from inside a mutation. Use a Convex Action, which can call external APIs and then invoke mutations for the database side-effects.

```typescript
// ✅ Correct — Action calls a provider, then records the result in a mutation
export const sendNotification = action({
  handler: async (ctx, args) => {
    const result = await resend.emails.send({ ... });
    await ctx.runMutation(internal.notifications.recordDelivery, {
      providerMessageId: result.id,
      ...
    });
  }
});

// ❌ Wrong — provider call inside a mutation
export const sendNotification = mutation({
  handler: async (ctx, args) => {
    await resend.emails.send({ ... }); // will timeout / break retries
  }
});
```

## Rule 8 — Validate all mutation arguments with `v.*`

Every mutation and action must declare its args using Convex validators. Never accept raw unvalidated input.

```typescript
// ✅ Correct
export const createService = mutation({
  args: {
    orgId: v.id("orgs"),
    name: v.string(),
    durationMins: v.number(),
    priceMinorUnits: v.number(),
  },
  handler: async (ctx, args) => { ... }
});
```

## Adding new tables

When adding a new table to `schema.ts`:
1. Include `orgId: v.id("orgs")` as the first field
2. Include `isDeleted: v.boolean()` and `deletedAt: v.optional(v.number())`
3. Include `createdAt: v.number()` and `updatedAt: v.number()`
4. Add `.index("by_org", ["orgId"])` as the first index minimum
5. Never edit `convex/_generated/` — it is auto-generated by the CLI
